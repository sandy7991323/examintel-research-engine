# Workflow 09 — Question Bank Generation

## Title

Comprehensive Examination Practice Question Bank

## Objective

Create a well-organized question bank that gives students a large pool of
practice questions covering the entire syllabus. Every question is categorized
by source, marks, difficulty, and topic — and every question's origin is
honestly disclosed.

---

## Required Inputs

| Input | Source | Required? |
|-------|--------|-----------|
| Extracted questions | `workflows/01-paper-extraction.md` output | Yes |
| Question analysis | `workflows/05-question-analysis.md` output | Yes |
| Syllabus topic map | `workflows/03-syllabus-research.md` output | Recommended |
| Previous year paper data | `workflows/04-previous-paper-research.md` output | Recommended |
| Topic research data | `workflows/06-deep-topic-research.md` output | Yes |
| Answer length rules | `config/answer-length-rules.yaml` | Yes |

---

## Step-by-Step Instructions

### Step 1 — Define Source Categories

Every question in the bank must carry one of these source category labels.
**This is non-negotiable — honesty about question sourcing is a core rule.**

| Category | Code | Description | Label in Output |
|----------|------|-------------|-----------------|
| **Original Paper** | A | Questions taken directly from the uploaded paper | `"Source: Original Paper (uploaded)"` |
| **Verified Previous Year** | B | Questions from previous year papers that were actually found and verified | `"Source: Previous Year Paper — [University] [Year]"` |
| **Frequently Repeated** | C | Concepts that appear repeatedly across PYQs, rephrased into practice form | `"Source: Based on frequently tested concepts"` |
| **Syllabus Important** | D | Questions generated from syllabus topics that haven't been tested yet | `"Source: Generated from syllabus — not from previous papers"` |
| **Additional Practice** | E | Extra questions for thorough preparation, generated by the engine | `"Source: Practice question (AI-generated)"` |
| **Application-Based** | F | Scenario-based and real-world application questions | `"Source: Application question (AI-generated)"` |

### Honesty Rules — Read These Carefully

> **RULE 1:** Never label an AI-generated question as a previous year question.
> If you created it, say so. If you found it in a verified paper, cite the year
> and university. There is no gray area here.

> **RULE 2:** Category B (Verified Previous Year) can ONLY be used when the
> question was found in an actual previous year paper during the research phase.
> If you're "pretty sure" a question was asked before but can't verify it,
> use Category C instead with an honest note.

> **RULE 3:** Category C questions must note which concept they're based on.
> Example: `"Based on the frequently tested concept: normalization (asked in
> 2019, 2020, 2022)."`

> **RULE 4:** Categories D, E, and F are openly AI-generated. The student
> must always know this. The label is mandatory — never hide it.

### Step 2 — Collect Questions from All Sources

#### Category A — Original Paper Questions

1. Copy all questions from the extracted paper (don't modify the text).
2. Preserve the original marks, section, and question number.
3. Tag: `source_category: "A"`, `is_original: true`.

#### Category B — Verified Previous Year Questions

1. From the PYQ research data, collect questions that were actually found in
   real papers.
2. For each, record: university, year, exam type, marks.
3. Tag: `source_category: "B"`, `verified: true`, `source_year`, `source_university`.
4. If the exact wording isn't available (you have only a topic mention),
   do NOT reconstruct a question and call it Category B. Move it to Category C.

#### Category C — Frequently Repeated Concepts

1. Identify topics that appeared in 2+ previous papers.
2. For each, generate 1–3 practice questions in the style of that university's
   exam pattern.
3. Tag: `source_category: "C"`, `based_on_concept`, `concept_frequency`.
4. Note which years the concept was tested.

#### Category D — Syllabus-Important Topics

1. Find syllabus topics with zero or minimal PYQ coverage.
2. For each, generate 2–4 questions at different mark levels.
3. Tag: `source_category: "D"`, `syllabus_unit`, `syllabus_topic`.
4. Focus on topics the student might skip because "they haven't been asked
   before" — these are exactly the ones examiners test when they want to
   surprise students.

#### Category E — Additional Practice

1. For every high-importance topic, generate 2–3 extra questions that test
   the concept from different angles.
2. Include a mix of question types: define, explain, compare, numerical.
3. Tag: `source_category: "E"`, `practice_focus`.

#### Category F — Application-Based

1. For topics that have real-world applications, create scenario-based
   questions.
2. Present a realistic situation and ask the student to apply the concept.
3. Tag: `source_category: "F"`, `application_domain`.
4. Example: Instead of "Explain ACID properties," write: "An online banking
   system processes 10,000 transactions per second. Explain how each ACID
   property prevents data corruption in this scenario. [10 marks]"

### Step 3 — Assign Metadata to Every Question

For every question in the bank, fill in:

| Field | Value |
|-------|-------|
| `question_id` | Unique ID: `QB-{category}-{number}` (e.g., `QB-A-001`) |
| `source_category` | A, B, C, D, E, or F |
| `marks` | Suggested marks (1, 2, 3, 5, 7, 10, 15) |
| `topic` | Primary syllabus topic |
| `unit` | Syllabus unit number |
| `question_type` | definition, explanation, comparison, numerical, practical, etc. |
| `difficulty_level` | easy, medium, hard |
| `suggested_time` | Minutes to answer (from `answer-length-rules.yaml`) |

**Difficulty level guidelines:**

| Level | Criteria |
|-------|----------|
| Easy | Direct recall or definition. Tests whether the student has read the material. |
| Medium | Requires understanding and some analysis. Can't be answered by memorization alone. |
| Hard | Requires synthesis, application, or critical thinking. Combines multiple concepts. |

### Step 4 — Organize into Sections

Structure the question bank into these sections:

```
QUESTION BANK
├── Section 1: Short Answer Questions (1–3 marks)
│   ├── Definitions
│   ├── Brief explanations
│   └── True/False or Fill-in-the-blank (if applicable)
├── Section 2: Medium Answer Questions (5–8 marks)
│   ├── Explain-type questions
│   ├── Comparison questions
│   └── Diagram-based questions
├── Section 3: Long Answer Questions (10–15 marks)
│   ├── Essay-type questions
│   ├── Discuss and analyze questions
│   └── Case study questions
├── Section 4: Numerical / Calculation Questions
│   ├── Formula-based problems
│   └── Multi-step calculations
├── Section 5: Practical / Programming Questions
│   ├── Code-writing questions
│   ├── Output-prediction questions
│   └── Error-finding questions
└── Section 6: Application-Based Questions
    ├── Scenario-based problems
    └── Real-world application questions
```

Within each section, order questions by unit, then by difficulty.

### Step 5 — Generate Answer Keys (When Requested)

If the user requests answer keys or model answers:

1. For Category A questions — use the answers from `workflows/07-answer-generation.md`.
2. For Category B questions — generate new answers following the same process.
3. For Categories C–F — generate concise model answers.
4. For short-answer sections, provide brief answer keys (1–3 lines).
5. For medium and long sections, provide structured model answers.
6. All answers follow the same writing style and quality rules as Workflow 07.

### Step 6 — Add Time and Marks Summary

At the end of the question bank, include a summary table:

```
| Section | Total Questions | Total Marks | Estimated Time |
|---------|----------------|-------------|----------------|
| Short Answer | 25 | 50 | 50 min |
| Medium Answer | 15 | 90 | 120 min |
| Long Answer | 8 | 100 | 120 min |
| Numerical | 10 | 50 | 75 min |
| Practical | 5 | 25 | 40 min |
| Application | 5 | 30 | 45 min |
| **Total** | **68** | **345** | **450 min** |
```

## Expected Outputs

| Output | Format | Description |
|--------|--------|-------------|
| `question_bank` | Object per `schemas/study-material.schema.json` → `question_bank` | Categorized question bank |
| `question_bank_md` | Markdown document | Formatted, printable question bank |
| `answer_keys` | Markdown or JSON (if requested) | Model answers for all questions |
| `source_transparency_report` | Markdown table | Category breakdown: how many questions from each source |
| `topic_coverage_matrix` | Markdown table | Topic → questions count → marks range → difficulty spread |

---

## Validation Requirements

- [ ] Every question has a `source_category` label — no unlabeled questions.
- [ ] No AI-generated question is labeled as Category A or B.
- [ ] Category B questions have verified source citations (year, university).
- [ ] Category C questions cite the specific concept and its frequency data.
- [ ] Categories D, E, F are clearly labeled as AI-generated.
- [ ] Every syllabus topic has at least 2 questions in the bank.
- [ ] The bank includes questions at easy, medium, and hard difficulty levels.
- [ ] Marks assignments are reasonable and consistent with `answer-length-rules.yaml`.
- [ ] No duplicate questions exist (even across categories — check for rewording).
- [ ] All questions conform to `schemas/question.schema.json`.
- [ ] The source transparency report is included and accurate.

---

## Error Handling

| Error | Response |
|-------|----------|
| No PYQ data available | Skip Categories B and C. Generate more Category D and E questions to compensate. Note the limitation. |
| Syllabus not available | Generate questions only from paper topics. Mark as "partial coverage" and note the gap. |
| Topic has no questions from any source | Generate 3–5 Category D questions. Flag the topic as "untested — high priority for study." |
| Duplicate question detected across categories | Keep the higher-priority category version (A > B > C > D > E > F). Remove the duplicate. |
| Marks allocation is ambiguous | Use the most common marks allocation for that question type at that university. Note the assumption. |
| Answer key generation fails for a question | Provide a brief outline or key points instead of a full answer. Mark as `[outline only]`. |
| Too many questions generated | Cap at 100 questions total unless the user requested more. Prioritize by importance level. |
| Too few questions for a topic | Generate additional Category E questions. Flag the gap in the coverage matrix. |

---

## Completion Criteria

This workflow is **complete** when:

1. The question bank contains questions from at least 3 of the 6 source
   categories (A is always present, plus at least 2 others).
2. Every question has complete metadata: source, marks, topic, unit,
   difficulty, time.
3. The honesty rules are fully satisfied — no misattributed sources.
4. The source transparency report is generated and accurate.
5. The topic coverage matrix shows every syllabus topic covered.
6. Questions span at least 3 mark levels (short, medium, long).
7. All outputs conform to their schemas.
8. The student can trust the source label on every single question.
